0. 한 장 요약

  • 사용자 데이터는 폰에, 서버는 계산만 하고 잊는다. 로그인 없음 · 서버 DB 없음 · 외부 API 없음
  • 서버 API는 2개: POST /match (달린 길 판정) · POST /routes (코스 추천) + 운영용 GET /meta · 헬스체크
  • 화면 약 40개 중 서버를 부르는 화면은 4곳: B0→B1(추천), C0→D1(러닝 종료), A4-3(기록 불러오기), 지도 버전 교체 시 재계산
  • 나머지(홈 지도 · 탐험률 · 내 코스 · 기록 · MY)는 앱 로컬 + 지도 파일(CDN)
  • 역할: A = 지도 데이터 · 정복 판정, B = 추천 · 서빙 · 프라이버시

1. 전체 구조

1.1 구성 요소

구성 역할 저장 담당
앱 기록 저장 · 정복률 · 화면 · GPS 필터 · 로컬 판정 사용자 데이터 전부 (로컬 SQLite) 앱 팀
지도 파이프라인 OSM → 길 조각 · 번호 → 지도 파일 지도 파일 (공공 데이터) A
API 서버 /match · /routes 계산 없음 A (판정) · B (추천 · 서버)
CDN 지도 팩 · 서울 인덱스 · 설정 배포 정적 파일 B (업로드)

1.2 설계 원칙 (위치정보 사업 미신고 전제)

  • 서버 무저장: DB · 파일 · 큐 · 캐시에 위치 미저장 · 요청 처리 후 즉시 폐기
  • 무식별: 로그인 · 토큰 · 기기 ID · 광고 ID 없음
  • 좌표 무로그: 요청 본문 · 예외 메시지 · 에러 추적 · 힙 덤프에서 제외
  • 제3자 미제공: 외부 API로 좌표 전송 없음
  • 경로 익명화: 앱이 시작 · 끝 300~800m 무작위 절단 + 시각 제거 후 전송

1.3 배포 형태

[앱] ──HTTPS──▶ [리버스 프록시 (TLS · 본문 미기록)] ──▶ [runveal-api 컨테이너 1개]
                                                          └ 이미지 = 서버 코드 + 지도 파일(현재 · 직전)
[앱] ──HTTPS──▶ [CDN] ◀── [S3 (지도 팩 · 서울 인덱스 · config.json)]
  • 서버 1대 (2 vCPU · 4GB) · 상태 없음 → 늘릴 땐 같은 컨테이너 복제
  • 없는 것: DB · Redis · 큐 · 워커 · 외부 API · 비밀 키 · 회원 시스템

1.4 서버 내부 구조

runveal-api (Spring Boot)
┌──────────────────────────────────────────────────────────────┐
│ ① 진입      실제 클라이언트 IP 추출                         B │
│ ② 보호      IP rate limit → 동시 실행 상한                  B │
│ ③ API       입력 검증 · 지도 버전 선택 · 에러 변환           B │
│ ④ 엔진      MatchEngine (A)      │  RouteEngine (B)          │
│ ⑤ 지도      MapData × 2 (현재 · 직전)                         │
│             GraphHopper 그래프 (B) · 길 번호 매핑 (A)          │
└──────────────────────────────────────────────────────────────┘
  전부 읽기 전용 · 요청 끝나면 아무것도 남지 않음
계층 하는 일 담당 상태
진입 · 보호 실제 IP · rate limit · 동시 실행 상한 B IP 카운터만 메모리
API 검증 · 버전 선택 · 엔진 예외 → HTTP 에러 B 없음
엔진 맵매칭(판정) · 코스 추천 A · B 없음 (스레드 안전)
지도 지도 파일 로드 · 그래프 · 길 번호 매핑 B(로드) · A(매핑) 읽기 전용

1.5 요청 처리 순서

요청
  ▼ 실제 IP 추출
  ▼ IP rate limit                  (초과 → 429)
  ▼ 입력 검증                      (실패 → 400 · 413)
  ▼ mapVersion → 지도 선택          (현재 · 직전 외 → 409)
  ▼ 동시 실행 자리 확보             (2초 대기 후 없음 → 503)
  ▼ 엔진 호출 (match | recommend)
  ▼ 엔진 예외 → 에러 코드 변환      (메시지에 좌표 없음)
  ▼ 응답 · 입력 폐기

1.6 기동 순서

① 이미지 안 지도 파일 2개(현재 · 직전) 로드
② 해시 검증 (파일 · GraphHopper 설정)     (불일치 → 기동 거부)
③ 그래프 메모리 적재
④ 워밍업 매칭 1건
⑤ ready = 200 → 트래픽 수신

1.7 코드 구조 (모듈)

runveal-backend/
├ contracts/   엔진 호출 모양 (입력 · 출력)            A · B 공동
├ core/        지도 로드 · GraphHopper 설정              B
├ match/       맵매칭 엔진                               A
├ route/       코스 추천 엔진                            B
├ api/         Spring Boot · 보호 · 검증 · 에러          B
├ pipeline/    지도 파이프라인 (Java + Python)           A
└ infra/       Dockerfile · CI · 배포                    B
  • match ↔︎ route 서로 참조 안 함 · Spring은 api만 앎
  • 둘이 맞출 것 = contracts (엔진 호출 모양) + 지도 파일 형식

3. 맵매칭 — POST /api/v1/match A

3.1 입출력

구분 필드 비고
입력 mapVersion · purpose(LIVE · IMPORT · REMATCH) · points [[lng, lat]] 점 10~2,000개 · 앱이 익명화한 사본
출력 segmentIds · matchedPath · matchedDistanceM · sigunguCodes 길 번호 = 지도 파일과 동일 체계

3.2 앱이 보내기 전에 (D13)

[원본 GPS (폰에만 저장)]
  ▼ 오차 30m 초과 점 제외 (거리 계산에서도 제외)
  ▼ 100m 또는 1분 미만 → 저장 안 함 · 전송 안 함 ("기록이 너무 짧아 저장되지 않아요")
  ▼ 시작 · 끝 각각 300~800m 무작위 절단 (러닝마다 새로)
  ▼ 시각 제거 · 10초 간격 다운샘플 · 튀는 점 제거
  ▼ 남은 점 10개 미만 → /match 안 보냄 · 전 구간 앱 로컬 판정
  ▼ POST /match
  • 단계별 상세 규칙: API 명세 §3.1

3.3 서버 처리

① 지도 버전 확인                    (현재 · 직전 외 → 409)
② 동시 실행 자리 확보                (없음 → 503 + Retry-After)
   └ IMPORT · REMATCH는 서버 전체 동시 1건 (LIVE 우선)
③ 그래프 범위 확인
     ├─ 전부 밖 → 422 OUT_OF_SERVICE_AREA
     └─ 일부 밖 → 범위 밖 점에서 끊어 조각별 매칭
④ 맵매칭 (GraphHopper)
⑤ 인정 규칙 적용                    (구간을 얼마나 지나갔는지 기준)
⑥ 응답 · 입력 폐기
  • 잘린 시작 · 끝 구간 + 러닝 중 실시간 색칠: 앱이 지도 팩으로 판정 (도로선 15m 이내 · 구간 길이 60% 이상)
  • 같은 입력 = 같은 출력 → 재시도 안전

3.4 기능 요구사항

우선순위 요구사항 비고
P0 맵매칭 + 인정 규칙 → 달린 길 번호 목록
P0 범위 밖 점에서 끊어 조각별 매칭 전부 밖일 때만 422
P0 실제 러닝 GPS로 정확도 평가 → 인정 규칙 튜닝 잘리고 10초로 줄어든 입력 기준
P0 앱 팀용 계산 설명서 + 정답 예시: GPS 필터 · 로컬 판정 · 정복률 · 다운샘플 앱이 서버와 같은 결과
P1 지도 버전 교체 시 정확도 회귀 확인 교체 게이트 (§7.3)

4. 코스 추천 — POST /api/v1/routes B

4.1 입출력

구분 필드 비고
입력 mapVersion · start(소수점 4자리) · end(null = 순환 · 지도 탭) · distanceM · preferUnexplored · exploredSegmentIds · filters · paceSecPerKm 거리 1~21km · 500m 단위 · 기본 5km · 안 가본 길 기본 ON
출력 routes[0..3] · warnings 경로 · 거리 · 시간 · 고도 · 고도 그래프 · 새 길 · 태그(최대 3) · milestones · 길 번호
  • exploredSegmentIds는 코스가 지날 수 있는 범위만 전송 (순환 = 출발지 반경 거리 × 0.6 · 편도 = 출발·도착까지 거리 합 ≤ 거리 × 1.1인 타원) · 최대 10,000개 (초과 413 TOO_MANY_SEGMENTS)
  • 필터: PARK(공원) · RIVERSIDE(하천길) · GENTLE_SLOPE(완만한 길) — 신호 필터 1차 제외 (D11)

4.2 처리

① 지도 버전 확인 · 동시 실행 자리 확보
② 요청 한 번짜리 가중치 생성                (달린 길에 벌점 · 저장 없음)
③ 도착지 있으면 최단 거리 확인
     └─ 최단 거리 > 선택 거리 → 200 + routes: [] + DESTINATION_FARTHER_THAN_DISTANCE + shortestDistanceM (→ B1-1)
④ 후보 코스 여러 개 생성
     ├─ 순환 → 후보 k개 · 목표 ±15%
     └─ 편도 → 우회 경로 · 목표 ±10%
⑤ 목표 거리에 가까운 순 최대 3개
     ├─ 0개   → 200 + 빈 배열 + NO_ROUTE_FOUND (→ B1-1)
     └─ 1~3개 → 경로 · 고도(≤100m 간격) · milestones · 새 길 · 태그
⑥ 응답 · 입력 폐기
  • 앱이 하는 것: B1 정렬(새 길 긴 순 → 요청 거리 근접 → 상승 고도 낮은 순) · 코스 이름(코스 A/B/C) · 저장(응답 1건 통째로)
  • 앱 타임아웃 10초 (Z0-1 → Z1-2) · 서버 마감 자리 대기 2초 + 계산 7초 · 서버 p95 목표 2초

4.3 기능 요구사항

우선순위 요구사항 비고
P0 순환 코스: 목표 거리 ±15% PoC 후보 5개 중 최선 → 100%
P0 편도 코스: 목표 거리 ±10% · 도착지가 멀면 빈 배열 + 경고 B1-1 연결 (D8)
P0 안 가본 길 우선 (요청별 가중치) PoC 새 길 비율 86.6% → 94.0%
P0 필터: 공원 · 하천 · 완만한 길 D11
P0 고도 그래프: 샘플 간격 ≤ 100m · 없으면 null B2 경사 3색 · 그래프 숨김 (D10)
P0 경로 정보 milestones: 도로 · 공원 · 하천 · 새 길 구간 + 누적 거리 이름은 OSM 태그 (D9)
P2 신호 · 횡단보도 필터 · 경유지 · 턴바이턴 안내 2차

5.1 산출물

  • 구 · 동 탐험률 = 로컬 explored_segments의 lengthM 합 ÷ 인덱스의 총 길이

5.2 처리

[OSM 원본 (버전 고정)]
  ▼ 그래프 생성 (GraphHopper import · 설정은 B 소유)
  ▼ 달릴 수 있는 길 추출
  ▼ 보행 회랑 병합 (나란한 보도 · 자전거도로 · 차도 → 한 길 · 분모 중복 9~27% 제거)
  ▼ 길 번호 부여 = hash(대표 way, 시작 node, 끝 node)   (다시 만들어도 같은 번호)
  ▼ 지도 파일 생성 (서버용 번들 · 구 팩 · 서울 인덱스)
  ▼ 불변식 검사 (번호 누락 · 총 길이 합 · 버전 일치 → 실패 시 배포 중단)

5.3 버전 정책

  • 같은 버전 파일은 재작성 금지 → 수정 = 새 버전
  • 같은 OSM 스냅샷이면 서비스 지역을 넓혀도 길 번호 불변 → 재매칭 불필요
  • 서버는 현재 · 직전 2개 버전 동시 탑재

7. 서버 공통 B

7.1 과부하 보호

장치 기준 초과 시
동시 실행 상한 CPU 코어 수 · 자리 대기 2초 503 SERVER_BUSY + Retry-After
대량 처리 (IMPORT · REMATCH) 서버 전체 동시 1건 대기 → LIVE 우선
IP rate limit /match 분당 30 · /routes 분당 10 · /meta 분당 60 429 (IP는 메모리 카운터만)
요청 본문 256KB (압축 해제 후) 413 PAYLOAD_TOO_LARGE

7.2 에러

기준: API 명세 §2.8 (코드 · 화면 매핑은 API 명세가 우선)

HTTP code /match 앱 동작 /routes 화면
400 INVALID_REQUEST FAILED · 재시도 안 함 Z1-2 (앱 버그)
409 MAP_VERSION_OUTDATED 지도 팩 갱신 후 1회 재시도 토스트 + 백그라운드 갱신 · B0 유지
413 PAYLOAD_TOO_LARGE · TOO_MANY_POINTS · TOO_MANY_SEGMENTS FAILED · 재시도 안 함 Z1-2 (앱 버그)
422 OUT_OF_SERVICE_AREA · MATCH_FAILED NO_MATCH · 기록은 저장 · 정복 반영 없음 (D1 안내) 토스트 · B0 유지
429 RATE_LIMITED Retry-After 후 백오프 재시도 Z1-2
500 INTERNAL_ERROR FAILED · 다음 REMATCH 때 재시도 Z1-2
503 SERVER_BUSY · ENGINE_UNAVAILABLE 대기열 · 백오프 재시도 · D1 분석 중 Z1-2
— (연결 실패) 대기열 유지 · 연결 시 재시도 Z1-1
— (앱 타임아웃 /routes 10초 · /match 15초) 백오프 재시도 Z0-1 → Z1-2
  • /routes 결과 0개는 에러가 아니다: 200 + warnings (DESTINATION_FARTHER_THAN_DISTANCE · NO_ROUTE_FOUND) → B1-1
